# Sale Playbook — продажа одного салона под ключ

> **Для автора, не для клиента.** Это твой чек-лист на каждую продажу.
> Клиентский документ — `docs/INSTALL.md`.
>
> Цель — ничего не забыть в 22:00 когда ставишь 15-му салону и голова кипит.
> Проходи сверху вниз, помечай галочкой, храни журнал продаж.

---

## Этап 0 — Demo flow для очной встречи (мастерская продажа)

> Сюда смотришь **за час до встречи** и **в туалете перед заходом в салон**.
> Это не сценарий-зубрёжка — это якоря. Не надо читать с листа, надо знать порядок и фразы-хуки.

### 0.0. До встречи (вечер накануне или утром)

> ⚠️ **КРИТИЧНО: у тебя уже есть боевой задеплоенный инстанс (`sabina-nails` или похожий).
> НЕ ЗАПУСКАЙ `seed_demo.sh` на нём — он сотрёт реальные данные клиента.**
> Для демо нужен **отдельный демо-инстанс** с `TENANT_SLUG=demo` (или `demo-nails`).
> `seed_demo.sh` защищён whitelist'ом (`{demo, demo-nails, manicure-demo, test, sabina-nails}`),
> но **не полагайся на whitelist** — заведи отдельный бот через BotFather, отдельный VPS-инстанс
> или хотя бы локальный docker compose с `TENANT_SLUG=demo` и **другим BOT_TOKEN**.
> Боевой бот клиента и демо-бот на встрече — **физически разные процессы, разные БД**.

- [ ] **Демо-инстанс — отдельный.** Не боевой `sabina-nails`. Отдельный `@my_demo_bot` с `TENANT_SLUG=demo`, своя БД, свой токен. Если ещё не создал — сделай **до первой встречи**, не в день встречи.
- [ ] **Демо-инстанс прогрет.** На демо-инстансе (НЕ на боевом) запусти `./scripts/seed_demo.sh` — должны быть 3 мастера, 8 услуг, ~70 записей, ~12 отзывов. Пустой бот = смерть демо. Открой демо-бота сам, проверь что «📅 Сегодня» показывает живые записи.
- [ ] **Два аккаунта Telegram готовы.** Один — админ (твой) для **демо-бота**, второй — «клиент» (второй TG-аккаунт или второй телефон). На встрече будешь переключаться: админский экран на ноуте, клиентский — на её телефоне.
- [ ] **На ноуте открыт ИМЕННО демо-бот, не боевой.** Перед заходом в салон проверь username бота в шапке чата — `@my_demo_bot`, а не `@sabina_nails_bot`. Спутаешь — покажешь владелице чужие персональные данные. Это конец карьеры.
- [ ] **Зарядка ноутбука >50%.** Розетка может быть занята феном.
- [ ] **Интернет резервный.** Раздача с твоего телефона включена и проверена. Wi-Fi салона — лотерея.
- [ ] **Знаешь имя владелицы и название салона.** Произнеси вслух 2 раза перед заходом — на встрече назовёшь без запинки, это +10 к доверию с первой секунды.

**Если у тебя ещё нет отдельного демо-инстанса — собери прямо сейчас:**

```bash
# на твоём ноуте или отдельном VPS
cd /opt/manicure-demo  # отдельная папка, НЕ /opt/manicure где боевой
git clone https://github.com/RiobVO/manicure.git .
./install.sh demo <твой_admin_id>
# в .env BOT_TOKEN — токен от @my_demo_bot, НЕ от @sabina_nails_bot
./scripts/seed_demo.sh
```

После этого у тебя **два бота**: боевой клиентский и твой демо. Никогда не путать.

### 0.1. Первые 60 секунд: не продавай

Не доставай ноут. Не говори про бота. **Спроси про её работу:**

- «Сколько у вас мастеров?»
- «Записываете в тетрадь, в Telegram, в WhatsApp или где?»
- «Что бесит больше всего? Звонки в нерабочее время? Двойные записи? Отмены без предупреждения?»

Слушаешь и **запоминаешь конкретные слова**, которые она использует («тетрадь», «двойные», «не приходят»). Дальше будешь говорить **её словами**, не своими. Это и есть продажа — она почувствует, что ты решаешь **её** боль, а не толкаешь свой продукт.

**Анти-паттерн:** начать с «у меня есть бот, он умеет...». 90% продаж убиваются здесь.

### 0.2. Хук под её боль (1 минута)

Услышав боль, дай **одну фразу** под неё. Не презентацию. Одну фразу.

| Её боль | Твоя фраза |
|---|---|
| «Звонят в час ночи» | «У меня клиенты сами записываются в боте 24/7. Без звонков. Покажу?» |
| «Двойные записи» | «У меня бот не даёт двух клиентов в один слот. Технически невозможно. Покажу?» |
| «Не приходят, не предупреждают» | «У меня бот за 2 часа напоминает клиенту. Доходимость стала почти 100%. Покажу?» |
| «Тетрадь, путаюсь» | «У меня всё в одном экране — день, неделя, мастера. На телефоне. Покажу?» |
| «Дорого YClients/AltegioCRM» | «У меня без подписки. Один раз заплатил — и навсегда твоё. Покажу?» |

«Покажу?» — **закрывающее слово**. Она кивнёт → ты достаёшь ноут. Она кивнула — она уже частично купила.

### 0.3. Демо: 5 минут, не больше

Порядок жёсткий. Не отступай — каждый шаг ведёт к следующему.

**Шаг 1 — клиентский опыт (1 мин).**
Дай ей **её телефон**. Скажи «представь, что ты клиент. Открой бота, запишись.»
- Она тапает «📅 Записаться» → выбирает услугу → мастера → дату → время → имя → телефон → подтверждение.
- Через 30-40 сек она получит «✅ Запись создана». В этот момент **на ноуте у тебя пинькает уведомление мастеру**.
- Скажи: **«Видишь? Она у себя записалась — я тут уже знаю. Ни одного звонка.»**

**Шаг 2 — админский экран (1 мин).**
Поверни ноут к ней. Открой «📅 Сегодня».
- Покажи 8-10 записей за день, с разными статусами (✅ оплачено, ⏳ ожидает, ❌ отменено).
- Тапни одну запись → откроется карточка с клиентом, телефоном, услугой, мастером, кнопками «📞 Позвонить», «🔄 Перенести», «❌ Отменить».
- Скажи: **«Это твой день одним экраном. На телефоне. В дороге, в маникюрном кресле, где угодно.»**

**Шаг 3 — killer feature: ➕ Записать вручную (1 мин).**
Это **самая важная демонстрация**. Большинство владелиц 35-45 лет принимают записи **по звонку**. Если бот не даёт принять звонок — они не купят.
- Из «📅 Сегодня» тапни ➕ → введи «Маша» → 998901234567 → выбери услугу → мастера → время → подтверди.
- Запись создалась за **10 секунд**. Мастер сразу получил пуш.
- Скажи: **«Звонит клиентка — пока разговариваешь, уже записала. Она не повесила трубку — а у тебя в системе уже всё.»**

**Шаг 4 — статистика (30 сек).**
Тапни «📊 Статистика».
- Покажи стрелки тренда (↑12% записей, ↓3% отмен), топ-3 мастера по выручке.
- Скажи: **«В конце месяца ты не считаешь в тетради. Ты видишь сразу.»**

**Шаг 5 — переключатель категорий (30 сек). Только если у неё НЕ маникюр.**
Если салон — стрижки/брови/массаж, открой «⚙️ Настройки» → «🏷 Категории» → переименуй «💅 Маникюр» в «✂️ Стрижки».
- Сразу покажи на её телефоне как клиент — кнопка изменилась.
- Скажи: **«Бот — твой. Не «маникюрный». Подстраивается под салон за 5 секунд.»**

**Шаг 6 — пуш надёжности (30 сек). Только если её муж/брат рядом и пытается «технически» допросить.**
Открой `/status`.
- Покажи uptime, последний бэкап, размер БД, мастеров онлайн.
- Скажи: **«Бэкап в Telegram-канал каждые 6 часов. Если умрёт сервер — за час восстановим. Данные у тебя, не в облаке стороннего сервиса.»**

### 0.4. Закрытие (2 минуты)

После демо **не спрашивай «ну как?»**. Это даёт ей паузу для сомнений.

**Спрашивай конкретно:**
- «Когда хочешь запустить — на этой неделе или на следующей?»
- «Сколько у вас мастеров — всех заводим сразу или сначала тебя?»
- «Бот заведём на твоё имя или название салона?»

Это **assumption close** — ты ведёшь себя так, будто решение уже принято, осталось согласовать детали. Если она не готова — она скажет «погоди, ещё подумаю». И **только тогда** ты отрабатываешь возражение. Не раньше.

### 0.5. Если она колеблется

Самые частые возражения и ответы. Каждый — **одной фразой**, без длинных объяснений.

| Возражение | Ответ |
|---|---|
| «Дорого» | «Год работы YClients стоит примерно столько же. У меня — навсегда.» |
| «А мои мастера разберутся?» | «Если они умеют WhatsApp — разберутся за 10 минут. Покажу инструкцию для мастера.» |
| «А клиенты будут пользоваться?» | «Каждый второй уже в Telegram. Кто не хочет — звонит как раньше, ты записываешь через ➕.» |
| «А если бот сломается?» | «Я твоя поддержка. WhatsApp/Telegram, отвечаю в день. Бэкапы каждые 6 часов — данные не теряются.» |
| «А если я уйду от тебя?» | «Архив всех твоих данных отдам в `.tar.gz`. Без блокировки.» |
| «Подумаю/посоветуюсь с мужем» | «Конечно. Я тебе сейчас пришлю короткое видео-демо в WhatsApp — покажешь дома. Когда принять решение — на неделе?» |

Последнее — критично. **Не отпускай без следующего шага.** «Подумаю» без даты = «нет».

### 0.6. После встречи (тот же день)

- [ ] **Через 1-2 часа** — написать в WhatsApp: «Спасибо за встречу! Вот видео-демо: [ссылка]. Если что-то непонятно — пиши, отвечу.»
- [ ] **Через 2 дня** — если не ответила: «Хотела ещё раз посмотреть? Могу заскочить на 15 минут.»
- [ ] **Через неделю** — если молчит: «Решила пока повременить или есть вопросы? Я бы хотел понять чтобы не дёргать зря.» Прямой вопрос → или конкретное «да», или конкретное «нет», или конкретная причина которую можно отработать.
- [ ] **Записать в журнал продаж результат**: купила / отказалась / думает + причина (своими словами, не интерпретация).

### 0.7. Анти-паттерны (за это бьют тапком)

- ❌ **Не показывай код, БД, docker-логи.** Никогда. Даже если муж — программист и просит. «Это под капотом, тебе не надо. Я отвечаю за то чтобы работало.»
- ❌ **Не говори «у нас в проекте/в коде/в архитектуре».** Говори «в боте/в твоём боте/у тебя».
- ❌ **Не сравнивай напрямую с YClients функция-к-функции.** Проиграешь — у них больше. Сравнивай **на её боли**: «у них есть, но за 1.5 млн в год; у меня — закрывает твою боль с двойными записями за один платёж».
- ❌ **Не извиняйся** за «у нас пока нет SMS» / «нет графиков». Просто «не сейчас, добавлю когда станет нужно». Извинения = слабость = «передумаю».
- ❌ **Не показывай больше 5 экранов.** Перегруз = страх = отказ. Лучше **меньше** и оставить «вау, а ещё что умеет?».
- ❌ **Не уходи без следующего шага.** «Я подумаю» без даты — это «нет».

### 0.8. Главный принцип

**Ты не продаёшь бот. Ты продаёшь решение её конкретной боли.**

Если она сказала «звонят в час ночи» — твой бот про **то что клиенты сами записываются**. Не про FSM, не про идемпотентные платежи, не про i18n. **Про тишину после 22:00.**

Каждое демо подгоняй под её слова. Один и тот же бот — три разные продажи трём разным владелицам.

## Этап 1 — Pre-sale: разговор с клиентом

Узнай **до** того как что-либо делать:

- [ ] **Контакт клиента** — Telegram @handle (чтобы писать напрямую).
- [ ] **Название салона** — для маркировки (не критично для кода).
- [ ] **Город** — нужен для `TIMEZONE`. Ташкент = `Asia/Tashkent`, Москва = `Europe/Moscow`, и т.д. (IANA-формат).
- [ ] **Есть ли VPS у клиента?** Если нет — ты арендуешь, включая в стоимость.
- [ ] **Telegram user_id админа** — того человека, кто будет управлять ботом.
  Как узнать: клиент пишет боту [@userinfobot](https://t.me/userinfobot) → получает числовой ID → присылает тебе.
- [ ] **Сколько мастеров** в салоне — информативно, влияет на то, как рассказать про кабинет мастера (v.3).
- [ ] **Согласована цена и срок поддержки.** Запиши словами что обещано.

Если клиент из Узбекистана — не забудь рассказать, что бот поддерживает `uz_UZ`
в будущем, но сейчас только русский (в `FUTURE.md` триггер на первого неруса).

## Этап 2 — Prep: подготовка на своей машине

### 2.1. Придумай `tenant_slug`

Правила: `[a-z0-9-]+`, без пробелов, без апострофов, без заглавных.

Примеры: `nails-chilanzar`, `beauty-mirzo`, `sabina-yunusabad`.

Не используй повторные `slug` — каждый должен быть уникален.

### 2.2. Создай Telegram-бота

Автор салона может сам, но чаще удобнее сделать самому и передать.

- [ ] Открой [@BotFather](https://t.me/BotFather) → `/newbot`.
- [ ] Имя бота: читаемое, типа «Салон Сабина — запись».
- [ ] Username: `sabina_nails_bot` (или аналог, должен кончаться на `bot`).
- [ ] Скопируй токен из ответа BotFather. **Это пароль от бота**, не шли через SMS / в переписку клиента.
- [ ] Опционально: `/setdescription`, `/setabouttext`, `/setuserpic` через BotFather — сделает бот человечнее.
- [ ] Опционально: `/setcommands` → `start - начать запись` (одна строка).

### 2.3. Выпиши 5-летнюю лицензию

```bash
cd ~/PycharmProjects/manicure
python tools/issue_license.py <tenant_slug> "<Название Салона>" 60
```

**60 месяцев = 5 лет.** Для первых 30 клиентов — всегда 60.

- [ ] Скопируй строку-ключ из stdout (длинная, `payload.sig`).
- [ ] Скопируй саммари из stderr — оно пойдёт в журнал продаж.

### 2.4. Запиши в свой журнал продаж

Веди отдельный файл у себя, **НЕ в репозитории** (там приватные данные клиентов).

Пример: `~/manicure-sales.md` (gitignored репозиторий или просто локальный файл).

Шаблон записи:
```
## 2026-04-21 · Салон Сабина

- tenant_slug:   nails-chilanzar
- customer:      Сабина Юнусабад
- contact:       @sabina_handle, +998 90 xxx-xx-xx
- tg_admin_id:   7082498953
- license_id:    <uuid из stderr>
- issued_at:     2026-04-21
- expires_at:    2031-04-20
- vps:           DigitalOcean NY3, IP 143.244.x.x
- bot_username:  @sabina_nails_bot
- bot_token:     stored in 1Password, note «Сабина»
- amount:        $XXX
- support_until: 2026-05-21 (1 месяц)
```

## Этап 3 — VPS: если у клиента нет

Пропусти, если у клиента свой VPS (просто попроси SSH-доступ).

### 3.1. Провайдер

| Провайдер | $ /мес | Где | Особенность |
|---|---|---|---|
| UzCloud (uzcloud.uz) | ~$5 | Ташкент | Локально, оплата в сумах |
| Hetzner Cloud | €4-5 | Германия | Дешёвый, надёжный |
| DigitalOcean | $6 | по миру | Классика, чуть дороже |

Минимум: **1 vCPU, 1 GB RAM, 20 GB SSD, Ubuntu 22.04**.

Для УЗ-рынка лучше UzCloud — клиент не думает про валюту, локация ближе.

### 3.2. Первичная настройка VPS

SSH под `root` (первый вход от провайдера):

```bash
# обновление
apt update && apt upgrade -y

# создать non-root пользователя (опционально, но правильно)
adduser salon && usermod -aG sudo salon

# docker одной строкой
curl -fsSL https://get.docker.com | sh
apt install -y docker-compose-plugin

# убедись что docker работает
docker run hello-world
```

## Этап 4 — Install: развёртка бота

### 4.1. Клонировать проект

```bash
cd /opt
git clone https://github.com/RiobVO/manicure.git
cd manicure
```

### 4.2. Запустить установщик

```bash
./install.sh <tenant_slug> <admin_id>
```

Интерактивно ответит на вопросы — держи под рукой:

- [ ] **BOT_TOKEN** (ввод скрыт) — из BotFather (шаг 2.2).
- [ ] **BACKUP_CHAT_ID** — твой приватный TG-канал для бэкапов всех клиентов. Создай один раз, используй везде. Как узнать ID канала: [@getidsbot](https://t.me/getidsbot). Начинается с `-100...`.
- [ ] **ERROR_CHAT_ID** — тот же канал или отдельный для ошибок. Можно тот же.
- [ ] **LICENSE_KEY** — длинная строка из шага 2.3.
- [ ] **HEARTBEAT_URL** — пока можно пропустить (пустой Enter). Триггер поднять свой endpoint — 3+ клиента.
- [ ] **LICENSE_CONTACT** — твой @handle, например `@plssog`. Будет в сообщениях «лицензия истекла, обратитесь к X».

Установщик сам:
- соберёт docker-образ,
- запустит redis, bot, autoheal,
- подождёт пока бот стартует,
- покажет последние 20 строк логов.

### 4.3. Проверить что всё поднялось

```bash
docker compose ps
# должно быть 3 контейнера: bot, redis, autoheal — все Up/healthy
docker compose logs bot --tail 30
# в логах ожидаемо: "License mode=ok ... Бот запущен"
```

### 4.4. Добавить бот в BACKUP_CHAT_ID и ERROR_CHAT_ID

Иначе он не сможет туда слать. В твоём канале:
- Управление каналом → Администраторы → Добавить администратора → найти бота по username → выдать права (минимум: отправка сообщений).

## Этап 5 — Smoke-тест (не пропускай!)

От своего аккаунта админа (тот user_id, что в `.env`):

- [ ] `/start` → появляется админ-панель с reply-клавиатурой.
- [ ] `/status` → видна строка `License mode=ok`, размер БД, uptime, Redis=✅.
- [ ] Добавь одну услугу через «💅 Услуги» → «➕ Добавить услугу».
- [ ] Добавь мастера через «👨‍🎨 Мастера» → «➕ Добавить мастера» (если их >1 — иначе дефолтный «Мастер» уже есть).
- [ ] Проверь «⚙️ Настройки» → «📅 График по дням» — дни недели настроены.

От другого аккаунта (свой клиентский, не админский):

- [ ] `/start` → приветствие нового клиента, кнопка «записаться».
- [ ] Пройди флоу до подтверждения записи.
- [ ] Админ-аккаунт должен получить пуш «🔔 Новая запись».

Если всё прошло — бот боевой. Если что-то упало — `docker compose logs bot` и дебаг.

## Этап 7 — Post-sale: что помнить

### 7.1. Первый месяц поддержки

Договорённость: первый месяц баги и вопросы — бесплатно. Дальше — платная поддержка либо на усмотрение.

Пиши в журнал что спрашивали чаще всего — это материал для FAQ.

### 7.2. Алерт об истечении лицензии

**Автоматически**: за 60 дней до `expires_at` бот шлёт тебе пуш в `ERROR_CHAT_ID` с именем клиента и готовой командой продления.

Для первых 30 с 5-летними лицензиями этот алерт сработает только через ~4.8 года — пока не думай.

### 7.3. Продление

Когда получил алерт:

```bash
python tools/issue_license.py <tenant_slug> "<Название>" 60
```

Выдаёт новый ключ → отправь клиенту инструкцию:

1. Откройте `.env` на сервере (`sudo nano /opt/manicure/.env`).
2. Замените `LICENSE_KEY=...` на новую строку.
3. `docker compose restart bot`.

Или сделай сам, если у тебя есть SSH-доступ.

### 7.4. Обновления кода (все клиенты сразу)

Когда пушишь новую версию в `main`:

```bash
# на сервере каждого клиента:
cd /opt/manicure && ./scripts/update.sh
```

Даунтайм ~30 сек. Можно автоматизировать позже через централизованный update-скрипт.

## Этап 8 — Авария / клиент ушёл

### 8.1. VPS умер

1. Возьми свежий бэкап из твоего TG-канала (ищи caption `[<tenant_slug>] backup ...`).
2. Подними новый VPS (Этап 3).
3. Восстанови через `docs/RESTORE.md`:
   ```bash
   git clone https://github.com/RiobVO/manicure.git /opt/manicure
   cd /opt/manicure
   ./install.sh <тот же tenant_slug> <тот же admin_id>
   # после установки:
   ./scripts/restore.sh ~/downloaded-backup.db
   ```

### 8.2. Клиент уходит

Запусти на его VPS:

```bash
cd /opt/manicure && ./scripts/uninstall.sh
```

- Заархивирует `data/`, `backups/`, `.env` в `/root/manicure-<slug>-<дата>.tar.gz`.
- Снесёт контейнеры и volumes.
- Архив — клиенту.

Запиши в журнал: «ушёл 2027-XX-XX, архив передан».
